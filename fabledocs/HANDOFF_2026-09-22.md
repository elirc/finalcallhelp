1. `cd cuedeck` and read this file's §4 status table to find the first batch that is not `done`.

4. Implement, test, update §4 and §5 here, commit with the attribution line.
5. Never run `vitest` and `playwright` at the same time on this machine.

Useful commands (from `cuedeck/`):

```
npm run typecheck && npm run lint && npm run format:check
npx vitest run test/unit/<file>.test.ts
npx vitest run test/integration/<file>.test.ts
npm run build && npx playwright test test/e2e/<file>.spec.ts     # E2E needs a fresh build
npm run check                                                   # format + lint + tsc + unit + integration (~2.5 min)
npm run test:e2e                                                # build + all 32 E2E (~4 min)
```

Gotchas learned so far:

- `vi.mock('electron', async () => { const { EventEmitter } = await import('node:events'); ... })` — imports inside the factory; top-level imports are not initialised when the hoisted mock runs.
- Prettier is part of `npm run check`; run `npm run format` on touched files before declaring a batch green.
- The first Electron E2E test occasionally times out once after a fresh `npm ci`; a rerun passes.
- `test-results/` is wiped by every Playwright run; the guide screenshots live in `fabledocs/images/`.
- Claude Code kills background shells when system memory is critical. Keep test runs in the foreground, split E2E runs per spec (or with `-g`), and ask the user to close VS Code/Chrome if free memory is under ~2 GB (`powershell -NoProfile -Command "(Get-CimInstance Win32_OperatingSystem).FreePhysicalMemory/1024"`).
- The Groq E2E fixture (`test/e2e/groqFixture.ts`) replaces `globalThis.fetch` in the main process; `__groqFixture.status` controls every route, `chatStatus`/`audioStatus` the two POST routes.
